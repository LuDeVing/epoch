## Open questions we cannot test on our bench yet

- Real-world bugs with the same tie rules and granularity, to compare LLM and spectrum on fresh data. We lack a fresh, uncontaminated bug set. Unblock: build a set from recent commits after the model's cutoff (SWE-bench-Live style, BugT style).
- Flaky tests, early termination and very few failing tests in LLM-based localisation (K35). We have no test harness that injects flakiness. Unblock: add a flaky and early-stop mode to the code bench.
- Human conflict (K09): Xie et al. (2016) is closed access and N is unconfirmed. Not needed for the agent; open only if a human arm is ever added.
- Strong 2025 to 2026 reasoning models on plain Ochiai hints (K26 covers only LLM localisers, not plain spectra). Needs model access in the bench, not new design.
- Value spectra versus an agent that prints variables (K30). Needs a probe tool in the harness.
- Whether the non-code spectrum (U3) generalises across problem classes. Needs canonical step forms for each class (ARC grid steps, word-puzzle claims, maths lines).
- Whether 3 to 5 attempts are enough for a spectrum at all. Classic work needed up to about 10 failing runs (a07). Unblock: run U3 with 3, 5, 10 attempts.

## Order to run

1. U1 and U2 together (same programs): the cheapest tests and the largest uncertainty; they say whether any spectrum hint is worth tokens for a strong model, and whether the executed-set filter saves them.
2. U3: the only test of the S5 idea on non-code reasoning, which is where our agent works; no study exists.
3. U4: a wrong hint is the main risk of adding any hint, so run it before U1's result is adopted.
