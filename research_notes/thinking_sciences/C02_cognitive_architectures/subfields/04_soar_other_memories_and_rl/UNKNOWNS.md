## Open questions we cannot test on our bench yet

- True numbers in Gorski and Laird Table 1 and Nason and Laird 2005. Unblock: get the primary PDFs (open-access copy or library access). Not decision-relevant for LLM agents, so low urgency.
- Direct Soar vs LLM-agent memory comparison on one benchmark (none exists). Unblock: port a minimal Soar-style episodic store into the harness (C02.04-U4 is the first step).
- Memory with a real hidden-state task. Our items rarely have identical visible state with different outcomes. Unblock: build a small synthetic item family with hidden rules.
- Effects beyond a few hundred records (scaling, forgetting policies). Unblock: a long-running stream of thousands of items; not available.
- Token-matched comparison of memory systems on published agent benchmarks (WebArena, AppWorld). Unblock: a harness that supports web or tool environments.
- Learned retrieve/skip policy by RL (Gorski and Laird style). Needs thousands of trials and a stable reward; skip.
- Memory-operation RL (Memory-R1). Needs training; outside the no-training rule.
- Current-model replications of Reflexion, Generative Agents, Voyager. Unblock: budget for re-running them on the current model.

## Order to run

1. **C02.04-U1** (distilled record vs raw vs none): the central bet for the S0 class record, cheap, and it also tells us whether to build the rest.
2. **C02.04-U2** (write-gate accuracy): decides whether S9 writes can be trusted, and sets the floor for every other memory test.
3. **C02.04-U3** (counts-based operator ranking): the only way to get Soar-RL value without training, and it reuses the logs from the first two tests.
