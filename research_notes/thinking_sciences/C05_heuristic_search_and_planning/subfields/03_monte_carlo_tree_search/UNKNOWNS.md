## Open questions we cannot test on our bench yet

- **A frontier reasoning model with UCT proper at equal tokens.** Only AB-MCTS (Thompson sampling, not UCT) has been run. Needs a harness that lets us pin tokens per arm for reasoning models and a set of at least 100 hard checked items.
- **A trained value or process reward model.** All the large gains (rStar-Math, AlphaMath, ReST-MCTS*, TS-LLM) need one. We cannot train. Unblock only if the project allows a small learned verifier; otherwise stay with code checks.
- **Environment rollback for agent tasks.** LATS, Koh and SWE-Search need a resettable environment. Our bench needs a replayable agent environment before the web or repository results can be checked.
- **Cheap difficulty estimation.** Snell's bins cost 2048 samples per question. We need a gate that costs a few percent of the budget; none is published with cost charged.
- **Natural deceptive trees.** No one has shown that the Coquelin-Munos worst case appears in real LLM reasoning trees. Needs logged trees from U3 with early-value versus final-outcome records.
- **Uniform token accounting.** LATS reports tokens only on success; SWE-Search's cost table is garbled. Our logs must count failed runs from the start.
- **True replications of the headline LLM-MCTS results** (rStar, MCTSr, RAP, LATS). None found. Would need their code and a compute-matched self-consistency arm.
- **Unreconciled numbers** (RAP GSM8K 48.8 vs 48.6 and 51.6; LATS k=50 0.63 vs 0.61; AlphaMath GSM8K 84.1). Resolve by reopening the tables if any of these are used as thresholds.

## Order to run

1. **C05.03-U3** (S6 tree vs best-of-N plus checker at equal tokens): it tests whether the tree already in the schema earns its cost. Every other search idea depends on the answer.
2. **C05.03-U2** (difficulty gate with gate cost charged): established harm on easy items, so the cheapest likely gain is turning search off.
3. **C05.03-U1** (check-scored tree vs repeated sampling on ARC-style items): the one place the literature shows an external-search gain on reasoning models, and it uses a code check we already have.
