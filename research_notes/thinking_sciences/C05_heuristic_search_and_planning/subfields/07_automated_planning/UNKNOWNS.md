## Open questions we cannot test on our bench yet
- Newer (2026) reasoning models were not in any source; we need our own runs to know where the length cliff sits now (needs bench runs with current models and hidden-token counts).
- A visual read of the garbled tables (GPT-4 Logistics rows, Guan Table 2, LLM+P other domains) would settle K10 and K08 details (needs the PDFs read by eye or a table extractor).
- A control that keeps predicate names but changes the dynamics (to separate memorisation from lost cues) does not exist; we would have to build such domain variants.
- Classical sources (STRIPS, Graphplan, FF, Fast Downward) were never opened; their measured speedups are missing (needs the PDFs).
- Silent-error rate of model-written transition code has never been measured by anyone (needs a labelled hand-made test set per domain).
- Whether verifier-loop findings hold for non-planning tasks with no formal checker (needs tasks with cheap code checks, or a trusted test oracle).
- Cost data for hand-written critics (engineering hours) is not reported anywhere in our sources.

## Order to run
1. **U1 (regression vs forward vs prose-backward):** it is the only direct test of O5, which has no STRIPS evidence at all, and it is cheap with code-held state.
2. **U2 (what the verifier loop gain is made of):** it decides whether first-error feedback or plain resampling is our default, and it shares items and code with U1.
3. **U4 (model-written transition program):** the largest possible gain (100% on tractable domains in Thought of Search) and the biggest unknown (silent errors), so one run settles whether code-held search can be a standard step.
