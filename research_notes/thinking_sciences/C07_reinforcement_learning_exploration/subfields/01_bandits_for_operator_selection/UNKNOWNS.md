## Open questions we cannot test on our bench yet
- **Real operator reward tables.** We have no full-factorial log (all 8 operators on every item). Cost is about 8x one pass. This unblocks U1 to U6 and U9 in replay. Run it before any live test.
- **Seed noise floor.** Run the same arm 10 times on the same items to get SD. Without it, a 2-point gap cannot be judged (published LLM-bandit gains use 3 to 6 seeds [critique]).
- **Counterfactual operator outcomes.** A live run only shows the operator that was picked. Replay needs either the full-factorial log or an offline estimator. No estimator has been validated for our setting.
- **Cross-task pooling for the prior (U3).** Needs enough classes (about 10) and a defined problem-class key from S0. S0 is itself an open slot.
- **Current frontier models as in-context bandits.** All evidence is 2022-2025 models at 25 to 500 rounds. Test only if we want the model, not code, to pick; G5 says no, so low priority.
- **TS-over-uniform at equal API calls.** OPTS tables give equal iterations, not equal calls; seed-level tests are impossible from tables. Needs a rerun or the authors' per-seed data.
- **Heavy-tailed rewards.** No published method for credit when the value of an operator is occasional breakthrough (Da Costa outlier case). Needs rank or quantile credit tests on our own logs.
- **Conflict with other subfields.** Restarts (anytime search), archives (Go-Explore) and quality-diversity may replace operator choice by choice of start state; compare once those briefs land.

## Order to run
1. **Full-factorial log, then U1 and U2 in replay** (uniform vs fixed order vs flat TS at 20, 40, 60 pulls): cheapest, decides whether any learner is worth building at 8 arms.
2. **U4 stall switch vs bandit-only vs both:** the sources conflict, and the S6 trigger already exists, so the live cost is small.
3. **U3 prior strength with held-out classes:** simulation says a modest right prior is the only thing that clearly pays at this horizon; check it on real logs.
