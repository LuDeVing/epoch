## Open questions we cannot test on our bench yet
- Value-versus-outcome calibration across LLM search states: needs logged intermediate self-scores and final outcomes for hundreds of runs.
- Model-strength threshold above which search stops paying: needs the same benchmark run on at least three model sizes of one family; we have one frontier model.
- Generalisation of the Hex 10x-to-15x train/test exchange to LLMs: needs controlled model families, no training access here.
- Search-trace training (Searchformer) and learned value heads: needs training; outside the scaffold-only scope.
- KataGo-style cyclic adversaries for LLM trees: needs an adversary search procedure; attacker agent (U15) is only a weak proxy.
- True Elo of frontier LLMs on chess: Carlini and Kaggle Game Arena pages gave no numbers; would need to run our own games against a fixed engine.
- Whether MCTS or alpha-beta style suits our tasks: needs branching factor and evaluation-cost measurements per item type.
- Whether reasoning-model chains contain implicit search: needs trace access; only final outputs are visible for some models.

## Order to run
1. E16.09-U2 (checker-ranked vs self-scored tree vs best-of-N): decides whether the S6 tree stays at all, and cheap to run on existing items.
2. E16.09-U10 (long chain vs wide short chains vs tree): decides the mode rule for reasoning models, the biggest token lever.
3. E16.09-U13 (early stop on easy items) together with U6 (band routing): cheapest big token savings, both use the same item set.
