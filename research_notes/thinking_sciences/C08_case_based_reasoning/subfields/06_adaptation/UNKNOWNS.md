## Open questions we cannot test on our bench yet
- Original adaptation-guided retrieval results (Smyth and Keane 1995, 1998), Wilkerson and Leake 2024, Leake and Ye 2021: paywalled. Unblock: library or author access. Until then U5 and U12 rest on a prior, not on numbers.
- A sound distance measure for text and reasoning items (U6). Embeddings are a placeholder. Unblock: check that embedding distance predicts base pass rate on our items.
- Frontier-model headroom: our bench may lack items hard enough to show an edit gain on the strongest model (U11). Unblock: build harder item sets.
- The human-feedback upper bound (Olausson 1.58x) cannot run in our loop. Use a strong tool or test as a proxy.
- Replicating DS-Agent, TextBFGS and CBR-to-SQL with our model: rebuilding their case banks is costly. Unblock: use our own solved items as the case bank.
- Whether the Game of 24 style gain (a stored Python solver) comes from reusing code rather than reasoning. Needs a test with code stored vs text stored.

## Order to run
1. U1, with U2 and U3 logged in the same run: it decides whether retrieve-and-edit earns its tokens, whether the case adds value beyond the verifier, and how often an edit breaks a right answer.
2. U4 with U11: a cheap diagnosis ablation on the failing items, split by base accuracy, which tells us where the edit stage should be switched on.
3. U6: the distance gate; it reuses U1's data and, if it holds, sets the S0 rule for when to edit and when to solve directly.
